## Decisions
- **D?split-formats** · 2026-10-27 · "Losslessly where the format allows" (05.11's Design) is implemented for MP3
  (frame-sync byte copy) and PCM/float WAV (exact sample-boundary cut) only. MP4/M4A/M4B would need a rebuilt moov
  sample table (`src/lib/meta/mp4.ts` only ever reads `stco`/`stsz`/`stts`/`stsc`, never writes them) — a much
  bigger, riskier rewrite than this chunk should take on, with no e2e coverage to catch a subtly wrong rebuild (the
  hermetic gate only walks the web build; this feature is native-only). A book in an unsupported format simply
  doesn't offer "Split into chapter files" on its menu. *Why:* correctness over completeness for a native-only,
  untestable-in-CI write path.

## Footguns
- **native-only-no-e2e-coverage** · a native-only on-device write path (`expo-file-system`, no web equivalent) has
  no hermetic test beyond the pure byte math it's built on; the real read/write loop needs a device to exercise →
  keep native-only I/O thin and push every decision it makes into a pure, `node --test`-covered function first ·
